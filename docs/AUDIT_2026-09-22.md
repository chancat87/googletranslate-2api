# 审计报告 (v1.6.0, 2026-09-22)

## 一、发现汇总

### [高] 真实上游 API Key 已进入 git 历史

- 证据: commit `f229883` ("Create .env") 包含真实 `GOOGLE_API_KEY` (AIza 开头, 41 字符), 后续 commit `72a9a65` 亦带 `.env`; 该 Key 当前仍有效 (本次 E2E 实测使用)。
- 影响: 仓库若公开, Key 属于泄露凭证; 高频使用也会被 Google 吊销。
- 处置: **需要你确认后执行**:
  1. 到 Google Cloud / 原抓包来源停用该 Key, 换新 Key;
  2. 按 `docs/rotate-key.md` 用 `git filter-repo` 清理历史 (不可逆, 需重写远端历史);
  3. 轮换后重新运行 `scripts/refresh_curl_appendix.ps1` 与 E2E。

### [高] 历史 Key 复测失效 (2026-09-22, v2.2.0)

- 证据: 用 `f229883:.env` 的 `GOOGLE_API_KEY` 启动 v2.2.0 复测，上游 `translateHtml` 返回 **400**，
  `e2e_smoke.py` 仅 14/20（ready/non-stream/cache/batch/认证语义受影响），进程日志同样为上游 400。
- 结论: 该历史 Key 当前不再可作真实上游验收，优先级从"建议轮换"提升为"必须轮换"；
  v2.2.0 的进程级 E2E 已用 mock 上游 20/20 兜底，真实 Google 路径需新 Key 复验。

### [中] 版本漂移 (已修复)

- `pyproject.toml` 停留在 1.2.0, 实际功能已到 1.5.x; 本次已同步为 1.6.0, 并保持 `APP_VERSION` / CHANGELOG / 文档一致。

### [低] Windows 多 worker 扩展受限 (平台事实, 非缺陷)

- Windows 无 SO_REUSEPORT, uvicorn 多 worker 共享监听 socket, 实测 4 worker 未提升吞吐; 生产多 worker 走 Linux 容器 + nginx/负载均衡。

### [信息] Redis 真实服务 E2E 未在本机执行

- 已尝试 WSL2 + Docker 运行真实 Redis 栈: 容器可启动且 redis/app healthy, 但本机 WSL2 Docker VM 周期性回收容器 (纯 `sleep` 对照容器 ~4 分钟 `exit 255`), 判定为环境限制。
- 代码路径已用 fakeredis 单测 + 死端口真实降级 E2E + Windows 原生真实 Key E2E 覆盖; 稳定 Docker host 上的真实 Redis 验收命令见 `docs/ACCEPTANCE_2026-09-22.md` 第六节。

## 三、建议

1. 优先处理 Key 轮换与历史清理 (见上);
2. 生产启用强随机 `API_MASTER_KEY` + `RATE_LIMIT_ENABLED=true` (或 nginx `limit_req`);
3. 生产日志 `LOG_FORMAT=json LOG_LEVEL=WARNING`, 接入集中日志;
4. Linux 部署后复跑 E2E 与压测, 确认多 worker + Redis 共享缓存的实际收益。
